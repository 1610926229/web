## 三、本轮的已知限制（**不是缺陷，是有意为之**，列出来免得被当 bug 报）

| # | 限制 | 原因 / 归属 |
|---|---|---|
| 1 | **「移除」护航不会释放他手上的单** | 需求只对 `enabled=false` / 封禁冻结了释放语义（EX-COMP-01/02）；`移除` 只有权限行，**没有任何订单联动规则**。自行补一条就是发明规则。已登记为遗留（`02-decisions.md` §12.2-2） |
| 2 | **对一位已经停用的护航再次停用，不会补做释放** | `areFlagsUnchanged` 未变即提前返回所致。正常运行下构造不出「已停用但订单还挂着他」（停用与释放在同一原子段）。出路是**按单走客服回池**。需求未冻结，不自行决定（`02-decisions.md` §12.2-3） |
| 3 | **换人后不会自动开始服务** | 裁定口径：新打手**自己**点「开始服务」。因此 C 段之后这一单停在 `accepted`，不是在 `serving` |
| 4 | 会话仍按 `orderId` 单键存储，**换人后新打手理论上能看到旧聊天** | ⚠️ 今天**不可达**：P0 打手端**没有任何聊天面**。等打手端聊天上线时必须按 assignment 隔离（EX-SERVICE-04）。已登记为遗留（`02-decisions.md` §12.2-1） |
| 5 | 客服**搜不到**用户资料页上的「平台展示 ID」（UUID） | P0-10 已登记的既有缺口（A9-9），本轮继承、**未扩大** |
| 6 | 超时 / 自动通过仍是**读路径上的惰性物化**，不是后台任务 | 仓库**没有 Scheduler**。真实 Scheduler 是**上线前 production blocker**，不是本轮遗漏；届时要调用**同一个**函数 |
| 7 | `tests/platformConfig.test.mjs` 的**偶发**（1 ms 时间戳） | P0-10 已登记的既有 `A9-3`，**非本轮引入，本轮不修**（不在范围内）。本轮 8 次连跑未复现 |
| 8 | 客服换人**没有幂等键** | 与 `StaffCompletionConsole` 同一条机制：幂等判据是**状态本身**（订单已不在履约中时服务端回 400），不是重放。与 `AdminApplicationActions`（幂等键）刻意不同 |
| 9 | 「停用」的接口响应里**没有**返回「释放了哪几单」 | 追溯仍然满足：每单各写一条 `CompanionReleaseRecord`，且 `/staff/orders/[id]` 与 `/admin/orders/[id]` 都能看到。**未顺手扩响应体**（MINOR，见 `03-delivery.md` §七） |
