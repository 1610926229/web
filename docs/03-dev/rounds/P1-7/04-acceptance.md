## 〇、开工前

### 怎么起服务

```bash
# 开发构建
ENABLE_MOCK_AUTH=true ENABLE_MOCK_DEBUG=true pnpm dev        # :3000

# 或按门禁用的生产构建（本文档所有数字都在这个构建上复算过）

  && ENABLE_MOCK_AUTH=true ENABLE_MOCK_DEBUG=true pnpm exec next start -p 3105
```

`ENABLE_MOCK_AUTH=true` 是**必须的**：没有它就没有模拟登录入口，`/mine` 会停在登录闸门上。
`ENABLE_MOCK_DEBUG=true` 只有 §I 的降级演示需要。

## 一、先说清楚：哪些**无法**人工复验，以及为什么

本轮的规格里有一批要求**在界面上不存在可复验的入口**——不是没实现，而是它们约束服务端行为，
界面**故意**不提供触发路径。逐条说明：

| 要求 | 为什么界面上复验不了 | 由什么证明 |
|---|---|---|
| 只有当前用户能读自己的老板数据；接口不接受任何「查谁」参数 | 页面自己不带这个参数，人点不出来 | 自动化：带 `?userId=u-1002` 请求，断言响应与不传时**逐字段相同**（`tests/bossStats.test.mjs`） |
| DTO 只有 8 个 key，不含 `orderId` / `orderNo` / `remark` / `refundReason` / `gameAccountId` / `userId` | `devtools` 里能看，但「**没有**某个字段」不是看一眼能确定的 | 自动化：对响应体断言**精确 key 集合**（多一个少一个都红）+ 六个禁止子串 |
| 五个指标全部服务端算，React 组件不遍历订单 | 组件不做聚合这件事**看不出来**——它做的事和「客户端算」长得一样 | 自动化：**扫源码**断言 `lib/constants/bossStats.ts` 与 `lib/services/bossStats.ts` 去掉注释后**不含 `refundedAmount`**（自己写第二份减法会立刻红） |
| 服务历史在订单 `accepted → serving` 的**同一原子区段**内写入，无 `await` | 并发与原子性不是人眼能看的 | 自动化：`tests/companionServing.test.mjs` 的原子区段门禁 + `appendCompanionService` 的去重/不可变性用例 |
| 存量历史由 `deriveLegacyServiceEvents()` **读时派生**（fail-closed、不 backfill） | 「没有伪造历史」是一个**否定式**断言 | 自动化：清空订单后断言派生结果；**人工部分**只能看「换人之后常用打手的次数是否真的增加」（见 §D4） |
| 未登录 401 | 页面在未登录时走登录闸门，看不到接口 | 自动化：匿名 `GET /api/me/boss-stats` → `401` |

**验收方式**：这部分请**以自动化测试的通过情况为准**（`pnpm test` / `03-delivery.md` 的终值），
不要因为「界面上点不出来」而判为未实现。

## 三、已知限制与**刻意的不对称**（请照此验收，不要当成缺陷）

1. **历史记录是「下界」（只少不多）。** `D10` 规定存量服务历史**不 backfill、不猜**，
   由 `deriveLegacyServiceEvents()` 在读取时派生。因此本轮上线**之前**发生过的「换人服务」，
   凡是旧模型里读不出来的，**不会**出现在常用打手里。这是**规则要求的**（宁可少、不可编）。
   验收 §D4 时，请用**新造的**服务动作来观察，不要拿历史订单对账。

2. **两个榜单的过滤条件**故意**不同**：`D6` 规定「常玩游戏」只算 `completedAt != null`（已完成），
   而 `D7` / `D8` 规定「常用打手」算**真实进入过 `serving`**（不要求已完成）。
   于是会出现 `u-1009` 这种**有打手、没有游戏**的用户（§F）。**这是两条裁定的直接结果**，
   不是漏了一个过滤条件；两句口径说明也分别写明了各自的口径。

3. **本轮**不提供：二级页 / 跳转 / 趋势图 / 图表 / 「再来一单」/ 打手行可点击 / 向打手发消息。
   这些都是 `D9` / `D11` 明确排除的，**不要**作为验收不通过的理由。

4. **`pnpm test` 现在是全绿的**（**1831 / 1831 pass / 0 fail / 0 skip**）。此前登记的那条
   既有 CRLF 失败已在**验收前收尾**中修掉，并顺带修掉了它暴露出的第二条假失败
   （「最近 30 天」断言随日历漂移）。改法与红绿验证见 `03-delivery.md` §2.3 / §2.4。

5. **`D10` 附加要求第 3 条（复用 assignment identity）本轮不做**——这条**已由产品正式收窄**
   （2026-10-02，逐字见 `02-decisions.md` §8.1）：服务事件只记 `order + companion + servingAt`
   的 append-only 历史，`(orderId, companionId, servingAt)` **只是本轮去重语义**、
   **不是**正式 Assignment identity。因此它**不是**验收项，**不要**以「没存 assignmentKey」为由判不通过。

6. **金额单位**：接口一律**整数分**，界面一律 `formatYuan`。看到 `24060` 应立刻读作 `¥240.60`。
