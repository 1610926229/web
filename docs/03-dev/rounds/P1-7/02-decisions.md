## 一、判据（`cmd_p1-next.md` 原文，8 条）

候选**必须同时满足**：

1. 已存在于需求文档 / 功能点进度表
2. 当前是 `PARTIAL` 或 `NOT_IMPLEMENTED`
3. **产品规则已经冻结**
4. **没有 `TBD — DO NOT INVENT`**
5. 不依赖微信 OAuth / 真实微信支付 / 真数据库 / 外部 Scheduler / 钱包 / 提现 / 负余额
6. 不需要用户现在回答问题
7. 不与 `DONE` 功能重复
8. 能独立人工验收

外加一句总则：「**遇到未冻结产品规则：不猜，标 BLOCKED，继续下一项。**」

判据 1 / 2 / 5 / 7 是**客观**的（看状态与依赖即可）；判据 3 / 4 / 6 需要**读需求**。
本轮的结论完全由 **3 / 4** 决定：P1 backlog 的每一族都**没有可供冻结的口径**。

## 四、为什么没有「退而求其次」的选项

- **不能挑「口径差异小」的硬做**：家族 G 是差异最小的一项，但它仍要在**两个语义不同的打手字段**间选择，

  按项目惯例应问产品（参见 `CLAUDE.md`：出现 TBD 禁止自行决定）。
- **不能把 `PARTIAL` 当 `DONE` 收尾**：`PARTIAL` 的缺口本身（如帮助中心的**内容**）正是未冻结的部分。
- **不能为凑数开发 P2 或生产功能**：`cmd_p1-next.md` 明文禁止。
- **不能自己给 P1 补一条需求**：Roadmap 变更不在本轮授权内。

## 六、交还给产品的问题（一句话版）
