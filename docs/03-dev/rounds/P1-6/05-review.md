### M2 `tests/adminCouponTemplates.test.mjs` 把断言失败**吞掉**，该用例永远不会红

**问题**（审查者原文指认的形态）：

```js
await expectApiError(create({ name: "后来的" }, key), "BAD_REQUEST",
  ADMIN_COUPON_OPERATION_CONFLICT_MESSAGE).catch(() => {});   // ← 吞掉
```

用例名承诺「幂等键被另一个操作用过 → 400 冲突」，但 `takeCreateReplay()`
在**同类型、同操作者**时判的是 `replay`（200），断言**必然 reject**，
`.catch(() => {})` 把它吃掉——冲突分支**一次都没被走到**，而且这条用例
在将来任何改动下都只能通过。给的是**假覆盖率**。

**处理（已完成）**：改写为**真的走到 `conflict` 分支**。
判据来自 `adminWriteSupport.ts`：`takeCreateReplay` 只在
「**目标类型不同**」或「**操作者不同**」时判冲突。因此改用
`createAdminCategory()` 先把同一个键用掉，再拿它新建券模板：

```js
const key = uniqueKey();
await createAdminCategory(ADMIN_ID, { idempotencyKey: key, gameId: GAME_DELTA, … });
await expectApiError(create({ name: "抢同一个键" }, key), "BAD_REQUEST",
  ADMIN_COUPON_OPERATION_CONFLICT_MESSAGE);     // ← 不再有 .catch
assert.equal((await adminTemplates({ keyword: "抢同一个键" })).total, 0);
assert.equal(couponStore().coupons.size, 6, "种子里 6 张，冲突路径一张都不该多");
```

> ✅ **红绿已验证**：把期望消息临时换成一个必然不同的常量，这条用例**变红**（`fail 1`）；
> 换回后复绿。证明断言是活的，不是又一次恒真。
> 这条用例现在覆盖的是**跨模块复用同一个幂等键**——单测券模板这一个模块测不出来。

## 五、登记为**后续项**（本轮不做，留给产品/后续 Round 裁量）

**`takeReplay` → `takeReplayForAction` 的跨模块收敛**（MINOR 1 与 2 的共同根因）。

`adminWriteSupport.ts` 已明文规定：**「意图在读到记录之前就已确定」的迁移类动作
必须用 `takeReplayForAction`**，否则「同键换意图」会被判成重放，
服务端**什么都不做却回 200**。券模板的启停恰好命中这条判据
（意图就是入参 `enabled`）。

**但现有五个模块**（护航 `setCompanionFlags`、类目、商品、协议、内容）**也都是 `takeReplay`**。
因此这**不是 P1-6 引入的偏差**，而是仓库级的一致状态。

**结论：不给券模板单独开小灶。** 单改一处会让它与五个模块分叉，
而「一条有时生效的规则，迟早会在不同模块里得到不同的解释」——
这正是 `takeReplayForAction` 的注释自己警告过的事。
本轮的处理是**登记**，不是**修**：跨模块口径统一应由产品/后续 Round 决定。
