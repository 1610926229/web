# P1-5｜打手排行榜闭环

## 目标
补齐真正的 Companion Ranking。当前用户消费榜不能冒充打手榜。

## Requirement Check
先从权威需求确认：
- 排名指标
- 周期（日/周/月/总榜等）
- 并列规则
- 上榜资格
- 展示字段

不得自行决定“收入最高就是排行榜”等产品规则。

若排名指标或周期仍未冻结：
- P1-5 标 BLOCKED
- 写出最小产品问题
- 不修改有争议业务代码
- 不猜
- 夜间批次继续结束，不等待人工

## 架构
复用现有 rank 模块、订单/Earning/Companion Repository，不创建第二套统计系统。

## 用户端
在现有 rank 入口增加真正的打手榜。
若权限表仍规定游客可浏览，则保持游客可见。

至少：
- 周期切换（按需求）
- 排名
- 打手公开头像/昵称
- 核心指标
- loading / error / empty

不得暴露手机号、实名、内部分账比例、敏感后台状态。

## 排序
主指标和并列规则按权威需求。
若业务规则未定义最终稳定键，但需要稳定分页，可用非业务 ID 作为最后稳定排序键，并明确它不改变业务并列含义。

## 测试
若未 BLOCKED，至少：
1. 空榜
2. 单打手
3. 多打手排序
4. 周期边界
5. 业务时区边界
6. 并列
7. stable ordering
8. disabled/removed 是否上榜按需求
9. 未完成/退款订单是否计入按需求
10. 用户消费榜不被污染
11. DTO exact keys
12. 游客权限
13. error/retry
14. 周期切换
15. existing rank 回归

## 不做
B/A/S 等级（除非已冻结且排行榜明确依赖）、推荐算法、实时 WebSocket、数据仓库。

## 门禁 / Git
完整门禁；禁止 Git 写操作。

## 结束
完成则 P1-5 = AWAITING_ACCEPTANCE。
需求不足则 P1-5 = BLOCKED。
不得开始 P1-6。
