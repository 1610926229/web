# 超哥电竞｜特殊情况与异常处理表

版本：V0.1  
基线日期：2026-09-19  
用途：作为异常分支、失败恢复、幂等、并发、售后、资金一致性和人工处理的开发基线。

> 本文件与《超哥电竞_业务流程表.md》《超哥电竞_用户权限表.md》配套使用。  
> 正常流程看业务流程表；谁能处理看用户权限表；异常发生后“系统到底怎么办”看本文件。

# 1. 异常处理统一原则

每一种异常至少要明确：

1. 谁触发 / 谁检测；
2. 前置状态；
3. 系统立即做什么；
4. 最终进入什么状态；
5. 钱如何变化；
6. 谁负责人工处理；
7. 是否通知；
8. 是否记录审计或领域事件；
9. 是否要求幂等；
10. 当前规则是否已经确认。

状态标识：

| 标记 | 含义 |
|---|---|
| ✅ | 处理规则已确认 |
| 🟡 | 规则已确认，功能正在实现/待验收 |
| ⏳ | 规则已确认，但后续批次实现 |
| ❓ | 尚未确认，不允许开发人员自行决定 |
| ⏸ | 当前明确不做 |

# 3. Checkout、支付与订单创建异常

| 订单状态 | 不生成 paid Order |
| 资金影响 | 无 |
| 状态 | ❓ 需确认“是否自动改为不指定”还是必须让用户重新确认 |

# 21. 核心原则汇总

1. **支付/退款/提现等资金事实优先于派生统计。**
2. **真实资金动作不能靠改状态伪装撤销，只能补偿/冲正。**
3. **deadline 是业务事实，scheduler/sweep 只是物化手段。**
4. **所有资金写入、接单、状态推进必须幂等。**
5. **公共池抢单必须原子。**
6. **历史指定打手与实际履约打手不能互相覆盖。**
7. **接单以后不允许打手主动放弃。**
8. **打手不能直接把订单标记 completed。**
9. **投诉存在时不能释放相关冻结收益，也不能删除关键聊天。**
10. **更换打手后新打手不能读取旧打手聊天。**
11. **管理员高风险动作必须审计。**
12. **任何待确认异常都不能由开发人员“顺手选一个方案”。**
